# LLM-Brain automatic-use contract

Unless `LLM_BRAIN_PASSIVE=0`, automatically resolve the current project in the configured LLM-Brain vault, perform one bounded read-only `maintenance status PROJECT_ID` check, and retrieve relevant effective OKF memory before every non-trivial project task. Stay silent when the maintenance report is current; emit at most one concise stale-only reminder when it is stale. At authorised closeout, capture the task and route durable candidates through review. LLM-Brain is active infrastructure; only the user experience is passive. Current source, governing instructions, explicit user direction and live proof outrank memory. Maintenance reports and schedule declarations are derived; never run, schedule, delete, retract, promote or inject them automatically. Never silently auto-promote protected material, and never require the user to name LLM-Brain. Set `LLM_BRAIN_PASSIVE=0` to suppress the automatic check, retrieval and capture. Keep OKF v0.2, storage schema 3 and the Hermes provider/context contracts unchanged.
