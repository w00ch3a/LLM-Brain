# Lexical profile v2: candidate for 0.10.0

Status: adopted as the default; shipped in v0.11.0.

## What changes

Lexical search (and so the lexical half of hybrid search, packs and recall)
uses a new BM25F profile, `v2`, by default. Fields, field weights, `b`
values, the phrase bonus and the `brain_paths` boost are unchanged. What
changes, each measured on held-out development sets before it was kept:

- **Light English stemming** replaces prefix matching (both records and
  queries use the same deterministic suffix rules).
- **Two-letter and numeric tokens** are kept (Pi, DB, CI, 5, 2026); the
  legacy scorer dropped every token shorter than three characters.
- **Identifier spans**: version strings, hosts, error codes, file names and
  kebab or snake identifiers in the query (`1.4.2`, `pi-vey14`, `E1234`,
  `config.py`, `PAGE_SIZE`) earn an IDF-weighted bonus when a record
  contains them intact.
- **camelCase parts and accent folding**: `getUserName` also indexes
  get/user/name; café matches cafe.
- `k1` is 0.9 (was 1.2).

Tried and dropped (no gain or a loss on the development sets): pseudo-relevance
feedback (RM3; it hurt every set), query stopword removal, a query-coverage
factor, bigram proximity, other `k1`/`b`/field-weight values and a
hand-written synonym list (not added: it would only encode the wording of
whatever test it was written against).

No model, no index, no new process: scoring stays inside the existing
`memory_signals` pass and takes the same time as before (27 vs 30 ms for a
401-record project, 120 vs 120 ms for 601 records, scoring only).

## Switch back

`LLM_BRAIN_LEXICAL_PROFILE=legacy` restores the 0.10 BM25F scores byte for
byte (checked on ten search cases and on the full official evaluation: all
350 queries return identical candidate lists). Any other value than `v2` or
`legacy` is refused with exit 64. Search metadata gains a
`lexical_profile=v2` line only when the new profile ran.

## Structural extensions (on by default)

Both are on by default under the `v2` profile and take `0` or `1` (any
other value exits 64); `legacy` ignores them. To opt out, set
`LLM_BRAIN_LEXICAL_ANCHORS=0` and/or `LLM_BRAIN_LEXICAL_STATE_ORDER=0`;
with both at `0`, `v2` returns exactly the scores it gave before the
extensions existed (checked on ten search cases).

- Link anchors (`LLM_BRAIN_LEXICAL_ANCHORS`) add an anchor field (weight 1.0, `b` 0.5)
  holding the link text and the title of every record that links to this
  one through a Markdown or `[[wiki]]` link. A record that is only ever
  described by the records pointing at it can then be found by those words.
- State order (`LLM_BRAIN_LEXICAL_STATE_ORDER`) looks at records sharing a
  `brain_state_key`. When every member of the group has an explicit
  `brain_valid_from` or `observed_at`, the newest one takes the group's best
  score (ties broken by date), so the current record ranks above the older
  ones. Groups with any undated member are left alone: missing validity is
  uncertainty and is never inferred.

Neither changes filtering: superseded, deprecated and expired records are
still filtered exactly as before.

Measured on a seeded structural evaluation (40 synthetic projects, 520
records, 240 queries per split; development and test use different names).
MRR@20, test split; ΔMRR against `legacy` with a paired bootstrap 95%
interval:

| Query type (40 q each) | legacy | v2, both off | v2 + anchors | v2 + state order | v2 default (both on) |
|---|---|---|---|---|---|
| current record, no supersession declared | .738 | .738 | .738 | 1.000 (+.263 [+.188, +.338]) | 1.000 (+.263 [+.188, +.338]) |
| record found only through links to it | .082 | .034 (−.048 [−.061, −.034]) | .197 (+.115 [+.091, +.142]) | .034 | .197 (+.115 [+.091, +.142]) |
| alias, tag, declared or expired supersession | .975–1.000 | 1.000 | 1.000 | 1.000 | 1.000 |
| all 240 queries | .799 | .795 (−.004 [−.010, +.004]) | | | .866 (+.067 [+.048, +.086]) |

Hit@20 over all 240 test queries: legacy 1.000, `v2` with both off .900,
`v2` default 1.000. The development split gives the same picture (all
queries .798 → .866, +.067 [+.048, +.087]).

The official sets contain no links or state keys, so both extensions leave
them unchanged (identical candidate lists). Under `v2` without anchors,
link-only records fall out of the top 20 for 60% of those queries (legacy
kept them all); the anchor field restores all of them, which is why both
are on by default. The structural set is synthetic (our own seeded
generator), so it shows the mechanism works, not how often real brains
need it.

## Evaluation (lexical only, no embedder)

hit@1 / MRR@20 / hit@20; ΔMRR with a paired bootstrap 95% interval.
Parameters were chosen on the development sets only.

| Set | Role | legacy | v2 | ΔMRR |
|---|---|---|---|---|
| synthetic dev (200 q, new entities) | dev | .725 / .794 / .950 | .750 / .818 / .960 | +.024 [+.004, +.044] |
| LLM-Brain-style dev (3000 q, hard negatives) | dev | .714 / .810 / .981 | .728 / .820 / .981 | +.010 [+.005, +.016] |
| SciFact train queries (809 q, 5183 docs) | dev | .574 / .655 / .857 | .611 / .678 / .860 | +.023 [+.008, +.037] |
| synth-eval (200 q) | test | .755 / .812 / .945 | .770 / .828 / .955 | +.016 [−.007, +.039] |
| scifact-eval (150 q) | test | .760 / .824 / .940 | .820 / .867 / .953 | +.044 [+.016, +.074] |
| paraphrase (205 q, ≤1 shared word) | test | .337 / .554 / 1.000 | .341 / .560 / 1.000 | +.007 [−.030, +.044] |

Reading it plainly: a clear gain on SciFact, a small gain on the synthetic
set that is not statistically certain at 200 queries, and no change when the
question shares almost no words with the record. That last gap is what the
optional embedder is for; word matching cannot close it. Most remaining
synthetic misses are near-duplicate records that differ only in details the
query does not mention.

Hybrid search: the lexical gate margin and z-score fusion alpha were tuned on
legacy lexical scores. v2 changes the score scale, so both are to be re-tuned
on top of v2 before release.
