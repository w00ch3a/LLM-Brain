# LLM-Brain v0.11.0

Released 2026-10-20. This release also ships everything prepared for 0.10.0,
which was not published on its own (see "Includes 0.10.0" below).

No vault migration. Storage schema 3 and canonical OKF v0.2 are unchanged.

## Review queue: only real exceptions

- Tiered review policy by default (`LLM_BRAIN_REVIEW_POLICY=tiered`). `strict` is byte-identical to the pre-0.11 behaviour for capture,
  closeout and promotion (covered by `tests/review-sweep-self-check.sh`).
- Capture writes source custody markers as `captured`, not `proposed`.
- `review sweep PROJECT_ID|--all --dry-run|--apply --confirm TOKEN|--undo RUN_ID`: a counts-only dry run, a
  token-confirmed apply with labels, audit rows and a manifest, and a working undo. Nothing is deleted.
- Tiers: CLOSE-custody, CLOSE-legacy, CLOSE-duplicate, AUTO-cooloff, AUTO-private, PARK, HOLD, FLAG-secret (left
  byte-for-byte as written and open for the owner) and FLAG-redaction (counted, untouched).
- Secret-bearing records (same detector as `secret-scan`) are owner-only wherever they sit: hidden from every named
  principal except `LLM_BRAIN_OWNER_PRINCIPAL`, and left out of `export knowledge-catalog` and `export bundle`.
  Nothing is redacted or blanked.
- `review sweep PROJECT_ID|--all --scan-sources`: read-only, counts-only secret census by area, file kind and
  detector, plus whether the custody behind a secret-like review item holds the same kind of text.
- Owner-only `private` sensitivity for auto-stored health, privacy, legal and finance facts: hidden from other
  principals and never replicated or exported. The evidence-graph traversal already fails closed for non-internal records.
- The `work run-once` closeout applies the policy only to candidates received after the project's start marker.
- New candidates record `brain_received_at`, which starts the cool-off clock (tiered mode only).

## Includes 0.10.0

All of the [v0.10.0 notes](v0.10.0.md) apply. In short:

- **Faster search and recall**, and hybrid search that uses z-score fusion and
  only calls the embedder when lexical search is unsure (gate 0.2, alpha 0.4).
- **Lexical profile v2 by default**: light stemming, two-letter and numeric
  tokens, identifier spans, camelCase parts and accent folding, `k1` 0.9.
  Link anchors and state order are on by default under v2. Opt out with
  `LLM_BRAIN_LEXICAL_ANCHORS=0` and/or `LLM_BRAIN_LEXICAL_STATE_ORDER=0`, or
  restore the old scores with `LLM_BRAIN_LEXICAL_PROFILE=legacy`. See the
  [lexical profile note](v0.10.0-lexical-candidate.md).
- Session handover, the ruled-out ledger, forgotten saves, health checks,
  automatic capture tags, careful belief updates, forgetting that sticks,
  procedure lifecycle, tried-and-reverted diffs and recall after compaction.
- Neural Expansion for Hermes Desktop.
- **Writer guard:** this version records a writer format level in
  `writer.format`. Upgrade every machine that shares a vault at the same time.

No embedding model is bundled or required. Fusion-protect is not part of this
release.

## Not in this release

- No reflector. Auto-promotion needs a local reflector (`LLM_BRAIN_REFLECTOR`), and that choice is still open.
- No evidence lane in search for captured, unreviewed sources.

## Upgrade notes

- Run `review sweep --all --dry-run` on each vault root before any apply. An apply needs explicit authority.
- Set `LLM_BRAIN_REVIEW_POLICY=strict` to keep the pre-0.11 review behaviour.
