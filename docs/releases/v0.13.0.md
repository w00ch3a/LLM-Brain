# Memthena v0.13.0 (formerly LLM-Brain)

Released 2026-11-13.

Fifteen memory-quality and safety changes, plus support for the Hermes 0.23 provider contract. Each change has its own behavioural self-check, and all of them run in the release gate. Two new Hermes options are off by default.

## Hermes 0.23

- **Provider contract.** The plugin now reads `initialize(resumed, message_count)`, so a resumed session finishes its pending captures instead of re-seeding. It also uses `on_turn_start(previous_message, model)` to re-warm recall after a resume, and it answers prefetch within Hermes' external-prefetch timeout, falling back to the context warmed after the last turn.
- **Subagent compaction no longer blocks.** A subagent fork's checkpoint is saved instead of raising, so `compression.checkpoint_required` no longer stops a fork from compacting.
- **Opt-in `raw_secret_custody` (off).** Hermes scrubs recognised secrets before every hand-off. With this option on, the plugin restores the exact original from Hermes' own local session store and keeps it owner-only (`restricted`, mode 0600). Restricted records never render in recall, packs or exports. With the option off, a scrubbed capture is labelled `egress_scrubbed`.
- **Opt-in `snapshot_host_memory` (off).** When on, each new primary session snapshots Hermes' `MEMORY.md` and `USER.md` into source custody. The files are only read.

## Safety and correctness

- **Stale writes are refused.** A writer whose record changed underneath it gets exit 75. The newer file stays, and the refused version is saved as a unique `.conflict-*` copy (#10).
- **Counterfactual check before cascading invalidation.** A dependent that still has surviving support is kept, and weak dependence is marked UNKNOWN. `LLM_BRAIN_COUNTERFACTUAL=0` restores the old plan (#11).
- **Fired intentions are assessed.** A fired intention is assessed as ACT or WAIT against its condition. A fire-once intention retires only on `intention done` (#12).
- **As-of packs abstain.** When records written by the as-of date don't settle a value, the pack says so instead of guessing, and later records are left out (#13).
- **Credit after use.** `feedback record --used` credits only the records that were actually used. Rarely retrieved records get an exploration slot. A merge or compression that drops answer facts is held for review (#14).
- **Point-of-use pack judgement.** `pack judge` reports which delivered records were new and which were used. `eval run` adds a "Point of use" table (#15).
- **Replaced versions are not promoted again.** A candidate that repeats an already-replaced version is deferred, and `--restore-superseded` allows a deliberate rollback (#1).
- **Current packs carry only current versions.** Recently changed records get a "Changed recently" notice. `LLM_BRAIN_PACK_CURRENT_ONLY=0` opts out (#2).
- **Reported preferences bind to the person who said them.** A quoted or forwarded preference is bound to its source. The claim projection is now `claims-v3` and is rebuilt on demand (#3).
- **Sources are counted, not voices.** Agent and session mentions of one claim count as one source. Independent roots are reported per record (#4).
- **The pack footer says what was left out.** It reads "Returned N of M matching records, about T tokens; K lower-ranked and J out of scope omitted." (#5)
- **Nested projects.** `project ensure DIR --nested` makes a folder inside a repository its own project. It sees parent memory only with `--inherits PARENT` (#6).
- **Conflict decisions are records.** `conflict decide|list` stores each decision tied to the hashes of both sides. The decision re-opens when either side is edited or retracted (#7).
- **Host-native memory snapshots.** `host-memory snapshot|list|diff` takes read-only snapshots of Claude Code, Codex and Hermes memory files, records them with their session ids, and shows the diffs (#8).

## Upgrade notes

- No vault migration. Storage schema 3, OKF v0.2 and the writer format are unchanged.
- Claim projections are versioned by file name, so `claims-v3` files are built alongside the old ones when they are needed.
- Upgrade every machine that shares a vault, so that all of them apply the stale-write refusal and the new promotion holds.
