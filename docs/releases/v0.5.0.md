# LLM-Brain v0.5.0

Version 0.5.0 adds a cognitive memory control plane and a first-class Hermes Agent integration while preserving Markdown as the durable authority.

## Highlights

### Hermes Agent memory

The standalone Hermes plugin provides automatic recall, durable turn capture and the `llm_brain_search` tool through Hermes' native `MemoryProvider` contract. An optional `ContextEngine` extends Hermes' existing compressor with request-scoped, provenance-labelled memory.

Hermes writes completed turns to an atomic Markdown outbox. A short-lived worker captures them into source custody, episodes and review without holding a project lease during slow work. Dead owners and timeouts leave recoverable state. Restricted tool results keep their hashes and call lineage without leaking excerpts or content-derived paths.

### Concurrent memory work

Project writers wait instead of exposing ordinary lock contention. LLM-Brain recovers a lock only after proving its owner died and retains a Markdown recovery receipt. Provider calls, embedding and index construction run outside the short commit lease.

Markdown work items now track `pending`, `running`, `committed`, `failed` and `superseded` states. Deterministic request IDs and atomic writes make capture, reflection and promotion retry-safe.

### Retrieval with evidence

Search and context packs accept intent, temporal, principal and evidence controls. Exact identifiers retain lexical matching. Current and as-of queries apply known validity intervals without inventing dates for older vaults. Evidence requests expand canonical results to episodes and source custody while reporting the actual fallback mode.

The evaluation harness compares no-memory, raw-source, episode, lexical, configured-vector, hybrid and graph retrieval under recorded budgets and source histories.

### Governed cognitive memory

Selective reflection prioritises corrections, decisions, requirements, contradictions and procedure outcomes. Reconsolidation creates review proposals instead of rewriting canonical memory. Procedure runs, outcome evidence, reversible projections, scoped visibility, associative links and usefulness records remain inspectable Markdown outside canonical OKF.

Prediction-error reflection and procedure replay ship behind separate disabled flags. Capabilities without supporting evidence remain negative gates rather than placeholder machinery.

## Compatibility

- Reads storage schemas 1, 2 and 3.
- Keeps OKF v0.2 as canonical semantic memory.
- Requires no daemon, database or new runtime dependency.
- Preserves legacy search and pack behaviour.
- Keeps the Hermes ContextEngine opt-in; MemoryProvider setup does not replace Hermes' default compressor.
