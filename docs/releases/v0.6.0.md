# LLM-Brain v0.6.0

v0.6.0 adds state-safe retrieval and reusable procedure preparation without changing storage schema `3`.

## What changed

- `search` and context packs support opt-in `--intent current_state` resolution with validity, retraction, visibility, supersession/version chains, dependency checks and explicit unresolved states.
- Selected results report independent root-source counts and correlated-record counts. Unknown provenance remains unconfirmed.
- Reflection candidates support `persist`, `use-now`, `reverify`, `ask` and `quarantine`. `LLM_BRAIN_COMMITMENT_POLICY=shadow` is the default; `legacy` preserves the old path and `enforce` applies the transition gate.
- `run prepare` creates a hash-bound, idempotent non-canonical `ProcedureCapsule`; `run start --capsule` rechecks its exact procedure, target, principal and task defaults.
- Hermes remains compatible with `memory.provider: llm-brain`, optional `context.engine: llm-brain`, its six configuration keys and native compressor. The search tool gains an optional intent, with factual retrieval still the automatic default.

## Compatibility and rollback

No vault migration, daemon, new dependency, model training, KV-cache integration or graph database is introduced. Existing factual, historical, bridge and capsule-free run commands keep their behaviour. New JSON and explain fields are additive, and older Hermes installations can ignore them.

Derived `CommitmentDecision` records, state warnings and procedure capsules are not canonical truth. Current-state resolution is never automatic, and Hermes never executes or injects capsules. To roll back, restore the prior package/skill and leave the schema-3 vault in place; no migration reversal is required.

## Verification

The release gate uses `tests/release-readiness-self-check.sh`; its `--release` mode requires the v3, work-queue, reflection-scheduler, temporal, retrieval-planner, procedure, reconsolidation, scope-feedback, Hermes, experimental, evaluation, compatibility, upgrade, packaging and presentation checks. Verify each packaged CLI and the Hermes manifest reports the value in `VERSION`.
