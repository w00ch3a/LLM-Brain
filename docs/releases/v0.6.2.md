# LLM-Brain v0.6.2

Version 0.6.2 packages the research-driven lifecycle safety improvements on
top of the schema-3, migration-free 0.6 line.

## Highlights

- Deterministic opt-in current-state resolution handles validity intervals,
  retractions, visibility, supersession/version chains, dependencies and
  unresolved conflicts without presenting uncertainty as fact.
- Commitment decisions (`persist`, `use-now`, `reverify`, `ask` and
  `quarantine`) are hash-bound derived records. `shadow` remains the default;
  existing promotion policy stays authoritative.
- Target-bound procedure capsules snapshot exact procedure/dependency evidence,
  support idempotent preparation, and provide read-only validation before a
  capsule-enabled run.
- Evidence intent exposes bounded, visibility-filtered lifecycle bundles and
  independent-source accounting. Incomplete relationships remain warning-first.
- The repository-only lifecycle evaluator covers twelve scenario families at
  20- and 200-event checkpoints, including poisoning, repair, provenance and
  capsule regressions.

## Compatibility and rollback

Hermes remains selectable as `llm-brain` with the existing MemoryProvider,
optional ContextEngine, six configuration keys, native compressor behaviour and
fail-open recall/capture boundaries. Factual retrieval remains the default;
current-state and evidence intents are explicit. Existing bridge fields,
capsule-free runs and `ingest-source` behaviour remain compatible.

No vault migration, daemon, database, model training, KV-cache integration or
new runtime dependency is introduced. Derived decisions, bundles, evaluator
reports and capsules are not canonical truth. Roll back by restoring the prior
package; leave schema-3 vault contents unchanged.

## Verification

Run `bash tests/release-readiness-self-check.sh --release` with the supported
Hermes Python environment, then verify that packaged CLIs and manifests report
the exact value in `VERSION` and that both archives have matching checksums.
