# LLM-Brain v0.7.1

Version 0.7.1 introduced bounded maintenance. Publication is not installation proof,
deployment, or a live-vault migration record.

## What changed

- Added bounded maintenance `preview`, `status` and explicit `run` commands
  for freshness, retention candidates, conflicts, work, receipts, indexes,
  provenance and retraction residuals.
- Added derived maintenance reports, visibility filtering and operator-declared
  host-native schedule markers. Maintenance never deletes, retracts, promotes,
  rebuilds indexes or installs a scheduler.
- Added the progressive-disclosure maintenance skill and refreshed the README
  with quick navigation, a documentation map and privacy-safe examples.

## Compatibility and safety

- OKF v0.2 and storage schema 3 remain unchanged. No vault migration is
  required, and no vault contents are rewritten by installation.
- Factual retrieval remains the default. Current-state resolution is opt-in.
- Hermes keeps `memory.provider: llm-brain`, the optional ContextEngine, six
  configuration keys, native compression and fail-open recall/capture.
- Reports, schedules, capsules, receipts and indexes are derived or working
  artefacts, not canonical truth. No daemon, database, zvec engine, cloud
  backend or new core dependency is introduced.

## Rollback boundary

If the release is rejected, restore the accepted source and package through the
governed Git workflow. Do not run migration or delete custody as a rollback
shortcut. Any live-vault upgrade remains a separately authorised operation.
