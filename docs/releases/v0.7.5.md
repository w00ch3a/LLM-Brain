# LLM-Brain v0.7.5

This release strengthens evidence custody and agent-host compatibility. A
published package is not proof of a local installation or live-vault migration.

## What changed

- Evidence and current-state context packs now put unresolved warnings first
  and prefer distinct verified source roots under tight budgets. They report
  truncation and incomplete evidence instead of implying that omitted evidence
  does not exist. `evidence_opened` is true only after authorised source bytes
  are read and match the expected SHA-256; this proves custody, not semantic
  support for an answer.
- Opt-in retrieval receipts retain their existing JSONL schema and fields, with
  an additive identity version that distinguishes principal, intent, as-of
  scope and the rendered selection. Existing receipts are untouched.
- The Hermes outbox worker uses profile-safe context where supported. Ordinary
  capture remains non-blocking; an operator who enables Hermes'
  `compression.checkpoint_required` gets a durable bridge-receipt requirement
  for direct-message capture, with failed capture preserving the uncompressed
  transcript. This setting can disable other compaction paths and needs an
  operator decision.
- Explicit OpenClaw staging accepts the tested 2026.9.2 and 2026.9.6 LLM-Brain
  export envelopes. It rejects private or cross-principal entries, duplicate
  session notes and unknown versions; it is not a native OpenClaw profile
  parser or a second canonical writer.
- The disposable lifecycle evaluator adds evidence-opened, citation,
  source-correlation, causal tool-evidence, compaction/restart and model-upgrade
  portability cases. Without an answer runner, model-answer quality remains
  **unmeasured**. Community contribution and issue templates are also included.

## Compatibility and safety

OKF v0.2 Markdown and storage schema 3 remain authoritative; JSON is transport
and receipts are derived. Factual retrieval stays the default and current-state
resolution stays opt-in. Hermes retains the `llm-brain` provider, its six
configuration fields, optional ContextEngine, native compressor behaviour and
fail-open recall. No vault migration, daemon, graph database, new core
dependency, automatic procedure execution or host configuration change.

## Rollback boundary

Restore the previously accepted source and package through the governed Git
workflow. Do not use live-vault migration, custody deletion or automatic
retraction as a rollback shortcut. Local upgrades remain separate operations.
