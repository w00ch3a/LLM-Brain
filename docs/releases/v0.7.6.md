# LLM-Brain v0.7.6

This patch release improves index preparation and retrieval guidance while
preserving storage schema 3 and canonical OKF v0.2.

- Index preparation batches OKF facts within the request. Each parsed result is
  bound to its source bytes, and publication rechecks source hashes, paths and
  effective inventory under the project lock. Document embedders receive the
  admitted immutable content snapshot as their input path.
- `search --help`, `search -h` and `search help` print supported options.
  Missing project or query arguments exit with a clean usage error.
- The retrieval skill checks exact names and aliases, the configured vault root
  and index coverage, source provenance and recency, and current tool capability.
  Historical success does not supply credentials or authorize new operations.

The accepted index-only patch measured a baseline median of 4.935 s and a
patched median of 3.231 s across
five alternating synthetic 26-record runs, with byte-identical derived outputs.
This is a fixture result, not a latency guarantee or a measured search speedup.
Filesystem caches were not flushed, and NAS performance was not measured.

No vault migration is required. No daemon, separate brain database or new
dependency is introduced. Visibility, strict duplicate-key rejection, parseability,
provenance and lifecycle checks retain their existing behavior.
