# LLM-Brain v0.8.0

This minor release adds memory signals and integration surfaces. Storage
schema 3 and canonical OKF v0.2 are unchanged. Every new signal is derived,
deterministic and rebuildable from canonical files. Nothing new can promote,
delete or rewrite approved memory without an explicit, audited command.

## Retrieval

- **BM25F lexical scoring** replaces the grep-count scorer. Field weights are
  title 3.0, metadata 1.5 and body 1.0, with field-length normalisation and a
  small phrase bonus. It uses only the Python standard library and recomputes
  scores from canonical files on every query, so no persisted index can drift.
  `LLM_BRAIN_LEXICAL_SCORER=legacy` restores the previous scorer, and installs
  without the new helper fall back to it automatically.
- **`brain_paths` globs** (optional, quoted, relative, no `..`) boost recall
  when the task text names a matching file or `search`/`pack build` receives
  `--path FILE`. Search metadata reports `path_hints` and `path_matched_count`.
- **Usage boost with a diversity guard** (`--usage-boost` or
  `LLM_BRAIN_USAGE_BOOST=1`) is opt-in. It applies a bounded multiplier from
  receipts and feedback. It reserves `LLM_BRAIN_DIVERSITY_RESERVE` (default 2)
  of the visible slots for relevant records with no recorded use, so popular
  records cannot crowd them out.

## Prospective memory and session start

- **Intentions** (`intention add|list|done|cancel`) record "do X when Y". The
  trigger can be a date, a path glob, a keyword or a change in the record set
  for a `brain_state_key`. They are operational files under `intentions/`, not
  canonical OKF. They are secret-scanned, audited and listed first, under "Due
  Intentions", in packs. Packs record `brain_intentions_due`.
- **Project brief** (`brief [PROJECT_ID] [--source-root PATH]`) prints a
  size-capped, read-only summary: durable approved facts, due intentions and
  recent changes. The SessionStart hook appends it fail-open with a 3-second
  timeout. Set `LLM_BRAIN_SESSION_BRIEF=0` to opt out. An unknown source root
  never creates a project.

## Maintenance signals

- **Advisory section** in maintenance reports, JSON (`advisories`,
  `advisory_counts`) and human output. Advisory signals never change health.
  - Retention candidates (never used, mostly not useful, idle) come from
    receipts and feedback. They are emitted only when usage evidence exists.
  - Memory-doctor findings cover orphans, likely duplicates (same title or
    body-shingle overlap) and oversized concepts.
  - Spaced re-verification suggestions.
  - Unverifiable code anchors.
- **Code anchors** (`brain_code_anchors: ["path@commit"]`): when git in the
  project's registered source root shows that the file changed after the
  anchored commit, maintenance reports a real `code-drift` finding with a
  `reverify` recommendation.
- **`usage PROJECT_ID`** lists use counts, usefulness and last-used dates.
- **FSRS-style stability** (`stability show`) derives stability from
  verification events and useful feedback, and shortens it after
  contradiction reviews. `stability apply PROJECT_ID ID --reason TEXT` is the
  only way to move `stale_after`. It is explicit, locked and audited.

## Review

- **Co-use proposals** (`association propose [--min-count N] [--write-review]`)
  find records that repeatedly appear together in packs marked useful.
  `--write-review` files `association` review items. Approving one builds the
  existing reversible AssociativeProjection.
- **Schema-fit triage** (`review triage`, `review list --triage`) orders the
  queue: conflicts first (`review-first`), then novel items (`standard`), then
  low-risk fits (`low-risk-batch`). Nothing is promoted automatically.

## Integrations and evaluation

- **MCP server** (`mcp serve [--read-only]`): a stdio JSON-RPC server with
  search, pack build, recall, status, brief and review-only capture.
- **Outcome harness** (`scripts/eval-outcome.py`) runs small coding tasks with
  memory on and off and scores them only with executable tests. On the bundled
  fixture, the deterministic reference runner passes 1/4 tasks with memory off
  and 4/4 with memory on. This shows the harness works. It does not measure
  any model.
- **Lifecycle interference family**: a thirteenth scenario family applies
  seven rapid supersessions to one fact. Only the newest version may reach
  retrieval.

## Compatibility

No vault migration is required. No daemon, database or new dependency is
introduced. The new Python helpers (`memory_signals.py`, `mcp_server.py`) ship
beside `okf.py` in the plugin and standalone packages. Unquoted globs such as
`brain_paths: [src/**]` are invalid YAML, so always quote them. Search ranking
changes because of BM25F; use the legacy switch if exact pre-0.8 ordering
matters.
