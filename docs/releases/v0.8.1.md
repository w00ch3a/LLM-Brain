# LLM-Brain v0.8.1

Released 2026-10-09.

This patch release fixes stale-lock recovery on Linux and a long-task pack
failure, adds opt-in Hermes plugin settings, and adds a reproducible Hermes
plugin archive. Storage schema 3 and canonical OKF v0.2 are unchanged.

## Fixes

- **Stale locks on GNU/Linux.** `lock_mtime` chained `stat -f '%m'` and
  `stat -c '%Y'` on stdout. GNU `stat -f` means `--file-system`: it printed
  filesystem details and failed, and that text was mixed into the timestamp.
  The result was never a number, so an ownerless lock directory (for example
  one left by a process that died between creating the lock and writing its
  owner file) was never treated as stale. Writers then waited forever, or
  until `LLM_BRAIN_LOCK_WAIT_SECONDS`. Each probe is now captured separately
  and must be a bare integer; GNU `stat -c` is tried before BSD/macOS
  `stat -f`. macOS behaviour is unchanged. `tests/lock-portability-self-check.sh`
  checks both stat dialects with shims, recovers an old ownerless lock and
  confirms that a fresh one is still respected.
- **Long `pack build --task` text.** Pack file names now cap the task part at
  80 characters, with the hash suffix keeping names unique. Before, long task
  text failed with "File name too long".

## Hermes plugin

The six selector keys written by `hermes memory setup` are unchanged. New
settings are opt-in: they are read when present in `llm-brain.json` and never
written as defaults.

- **Local Laya recall filter** (`laya_url`, off by default). When set, a recall
  with up to four results is sent to a local typed-decisions endpoint, and only
  results it rates relevant are kept. The endpoint must be `localhost` or a
  loopback, private or link-local IP literal. Redirects, proxies, embedded
  credentials and public addresses are refused. Sensitive-looking text is
  redacted before sending. The filter is fail-open: a timeout
  (`laya_timeout_seconds`, default 4), connection error, malformed answer,
  unclear margin or too many candidates returns the normal recall, with the
  reason in an additive `local_laya` field.
- **Bridge timeouts stop the whole process group.** A timed-out recall or
  capture used to stop only the CLI shell, leaving its descendants running
  and holding or waiting for the vault lock on slow (for example NAS)
  storage. Bridge calls also set `LLM_BRAIN_LOCK_WAIT_SECONDS=2` unless the
  environment already sets it, so lock contention fails quickly and capture
  retries from the outbox.
- **`context_engine_registration`** (`always` by default, or `when-selected`).
  Hermes has one plugin context-engine slot. `when-selected` registers
  LLM-Brain's engine only while `context.engine` is `llm-brain`, leaving the
  slot free for another context-engine plugin. Memory-provider recall and
  capture are unaffected.
- Setup rewrites of `llm-brain.json` keep keys owned by other integrations in
  the same file instead of dropping them.
- Secret redaction also covers AWS access-key IDs and AWS key assignments.

See the [Hermes plugin guide](../../integrations/hermes/llm-brain/README.md#opt-in-settings).

## Packaging and evaluation

- `scripts/package-hermes-archive.sh` builds
  `dist/llm-brain-VERSION-hermes.tar.gz` and its `.sha256`. The archive is
  byte-reproducible, with fixed owners, timestamps and 0644/0755 modes (the
  hand-built 0.8.0 archive used owner-only modes). The release gate rebuilds
  and compares it.
- The real-agent evaluation suite (`evals/real/`, checked by
  `tests/real-eval-self-check.sh`) runs synthetic coding and research tasks
  with memory on and off through `codex exec`, graded by hidden tests and a
  deterministic answer key. It is repository-only and not packaged.

## Upgrading

No vault migration is required. Standalone and plugin hosts upgrade as usual
with `upgrade check`, `upgrade apply` and `upgrade verify`. Hermes installs
replace `$HERMES_HOME/plugins/llm-brain` with the contents of the Hermes
archive and point `cli_path` at the 0.8.1 CLI. Existing `llm-brain.json` files
keep working unchanged. Hermes picks up the new plugin after a restart.

## Compatibility

No daemon, database or new dependency is introduced. The Laya filter uses only
the Python standard library and talks to an endpoint you run yourself.
