# LLM-Brain v0.8.2

Released 2026-10-09.

This patch release surfaces corrections and retractions to agents, makes index
builds work on network shares without symlink support and on legacy projects,
and makes evidence recall fast on slow storage. Storage schema 3 and canonical
OKF v0.2 are unchanged.

## Recall of corrections and retractions

- **"Corrections and Retractions" in packs and briefs.** Active records that
  supersede another record, and retractions with their reason, are shown in
  their own section whether or not they share words with the task (most
  task-relevant first, at most `LLM_BRAIN_PACK_NOTICES`, default 6). The
  section says that a local copy of a corrected or retracted document is the
  outdated version, and asks agents to cite the correction or retraction
  notice together with the original. Superseded or retracted content is not
  shown, and nothing is shown for records hidden from the current principal.
- **Fuller brief summaries.** Briefs keep whole leading sentences up to the
  summary cap, so "Correction: X corrects Y." keeps the corrected value.
  Retraction lines name the retracted record and the reason.
- **Brief header.** Current sources outrank memory, except where memory
  records a later correction or retraction of that same source.
- **Keyword intentions** also match simple inflections: "recommend" fires a
  `keyword:recommendation` trigger, reported as `keyword-stem~`.

In the repository's real-agent evaluation (10 research memory tasks, 3
repeats, Codex), memory-on pass rate rose from 30% to 67% (memory-off 10%).
The r10 grader check was also corrected: it failed answers that cited a
withdrawn dataset while saying it was withdrawn.

## Index builds and recall on network storage

- **No-symlink filesystems.** `index build` aborted on CIFS/SMB mounts
  without `mfsymlinks` after publishing the new generation, which left
  `rebuild-state.json` at `building` (maintenance: `rebuild-pending`).
  Compatibility aliases now fall back to copies. Rerunning `index build`
  clears a stuck state.
- **Legacy projects without `audit.v2.tsv`.** Audited writes, including
  `index build`, no longer abort; the hash chain starts fresh. No migration is
  performed.
- **Faster evidence recall without an evidence index.** Recall no longer
  opens every source file each time. Source metadata is cached in the derived
  `indexes/evidence-sources-meta.tsv` and re-read only for new or modified
  sources. On a 1,305-source project on a CIFS NAS, bridge recall fell from
  19-33 s to 3-5 s with identical output.

## Upgrading

No vault migration is required. Upgrade as for 0.8.1: standalone and plugin
hosts with `upgrade check`, `upgrade apply` and `upgrade verify`; Hermes
installs replace `$HERMES_HOME/plugins/llm-brain` with the Hermes archive and
point `cli_path` at the 0.8.2 CLI, then restart Hermes. Rerun
`index build PROJECT_ID` on projects whose maintenance status shows
`index:primary` as `rebuild-pending`.

## Compatibility

No daemon, database or new dependency is introduced.
